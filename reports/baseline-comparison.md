# 基线对比实验：代号一致性 / 身份残留率 / 串号率

> 三条路径跑同一批语料、同一份原文，比的是「这份数据交出去之后，研究方还能不能用」。数字由 `scripts/compare_baseline.py` 重跑即可复现。

三条路径各有各的坑：**朴素替换**一致但串号（所有患者共用同一批占位符，交付出去分不清谁是谁），**无一致性 hash** 不串号但跨材料对不上人（每份材料独立加盐），**本产品**两项都要。残留率另开一列：两条基线的字典来自主索引读回记录，覆盖不到手机号、完整身份证与检查号，产物里原样留着。

## 三、三条路径

### 本产品（一致代号档）

产品主路径：识别 → 按策略处置 → 残留自检；一致代号 = HMAC-SHA256(密钥, 方案名 + 患者主索引主键)，取值输入只有主索引主键

### 朴素查找替换

拿主索引读回记录建「原文 → 固定占位符」字典，正文里纯字符串替换；字典覆盖不到手机号、完整身份证（主索引给的是掩码值）与检查号

### 无一致性 hash 替换

与朴素路径同一份字典，但每一处命中算一个独立代号：H- + sha256(材料 ID + 命中原文 + 出现次序)[:16]，每份材料独立加盐

两条基线共用同一份字典 —— **HIS 患者主索引读回记录**，字段只有 `patient_id` / `visit_no` / `name` / `id_card_masked` / `birth_date` / `sex`。这一份字段清单本身就是一条发现：**主索引读回的口径不足以支撑「按字典替换」**—— 手机号压根不在里面，身份证给的是掩码值（正文里是完整 18 位），检查号是每次检查独有的、任何患者记录里都没有。

## 四、指标定义与算法

**身份槽位** = 姓名槽（`PATIENT_NAME`）与患者编号槽（`PATIENT_ID`）。

只有这两处指认「**这是谁**」。手机号 / 出生日期 / 身份证是「证明是谁」的直标识（脱掉即止，不构成代号）；住院号 / 检查号标识「**哪一次就诊**」，不是人 —— 把就诊槽算进代号，会因为「都写了 `<住院号>`」而把所有患者判成串号，那是误判，不是发现。

**代号集合 `T(m)`** = 该路径在身份槽位里写下的替换文本集合。

| 指标 | 定义 |
|------|------|
| 代号一致性 | 同患者材料对中 `T(m1) ∩ T(m2) ≠ ∅` 的对数 ÷ 同患者材料对总数（同一患者的材料能不能靠代号对上号） |
| 身份残留率 | 产物里阻断级身份残留处数 ÷ 原文身份类 / 就诊编号类命中处数（产物里还剩多少身份） |
| 串号率 | 不同患者材料对中 `T(m1) ∩ T(m2) ≠ ∅` 的对数 ÷ 不同患者材料对总数（会不会把两个不同的人误并成一人） |
| 一人一码率（补充） | `|T(m)| == 1` 的（材料, 患者）样本比例（一位患者在一份材料里被写成了几个代号） |

分子分母口径：残留统计用产品自己的残留自检（身份类 / 就诊编号类 → 阻断级；通用数字类只提示不阻断）；原文命中数用产品自己的识别器按同一套分级统计，**三条路径共用同一个分母**（同一份原文）。

**已脱产物的抑制口径三条路径一致**：产品自认自己的占位符与一致代号（命中即抑制，不算残留）；基线自己写出去的替换文本（占位符 / hash 代号）按同一套口径抑制。否则「住院号：H-xxx」会被字段标签识别器当成漏脱 —— 那是替换文本，不是身份；不抑制的话，基线会因为「代号长得不像本院格式」而多背一处残留，那是尺子偏了，不是泄露。

## 六、逐项解读

### 6.1 代号一致性 —— 同一患者的材料能不能对上号

- 本产品 100.00%：代号由**患者主索引主键**经 HMAC 算出，同一位患者在任何一份材料里都落到同一个串。
- 朴素替换 100.00%：也能对上号 —— 但代价是所有患者共用同一批占位符（见串号率）。
- 无一致性 hash 0.00%：**跨材料完全对不上人**。每份材料独立加盐，同一段原文在两份材料里得到两个不同的串。这条路径的出发点通常是隐私侧诉求（「别让人把两份材料关联起来」），但代价是研究侧拿到的材料成了无法关联的碎片 —— 一致性与不可关联性在这一条路径上被绑成了同一件事。

### 6.2 身份残留率 —— 产物里还剩多少身份

- 本产品 0.00%（残留 0 处）：识别层覆盖到手机号、出生日期、完整身份证、检查号，处置层逐类改写，残留自检再扫一遍 —— 拦投放行。
- 朴素替换 42.86%（残留 1500 处）、无一致性 hash 42.89%（残留 1501 处）：两条基线的字典都来自主索引读回记录，**字典覆盖不到的字段原样留在产物里** ——手机号（主索引读回格式里没有）、完整身份证（主索引给的是掩码值）、检查号（每次检查独有，任何患者记录里都没有）。

### 6.3 串号率 —— 会不会把两个不同的人误并成一人

- 本产品 0.00%：代号取自主索引主键，同名不同人拿到的串必然不同。
- 朴素替换 100.00%：**所有患者共用同一批占位符** —— 交付给研究方之后，任何两份材料都能被关联成「同一个人」。
- 无一致性 hash 0.00%：加盐把跨材料关联掐断了，代价是上一节的跨材料对不上人。

> 附带一条风险提示：如果把 hash 的加盐去掉（直接对**命中原文**做摘要），两位同名的不同患者会拿到同一个串 —— 本语料里 63 位患者只有 20 个姓名，这条坑一踩就是一片。**按原文做 hash 不等于一致代号**，一致代号的取值输入必须是权威身份键。

### 6.4 附带发现 · 代号本身也可能撞上身份形态

无一致性 hash 路径的残留率（42.89%）比朴素替换（42.86%）高出的那 **1 处**是「**形态碰撞**」：hash 代号是 16 位十六进制摘要，摘要里偶尔会出现 11 位连续数字，被联系方式识别器判成手机号 —— 残留自检把它算成一处漏脱。

形态碰撞**不是泄露**（那是替换文本，不是身份），但它是个真问题：**代号的字符集与院内编号形态撞了车**，收件方的自检工具同样会误报，值班的人要为此白查一轮。一致代号用固定前缀 + 固定位数十六进制，形态是收敛的 —— 本轮实测中本产品路径的形态碰撞为 0 处。

## 八、边界与诚实标注

- 语料是**合成数据**，不是院内真实数据；真实报告的字段分布比这更杂，指标数值会变，**结论的方向**（一致 / 串号 / 残留三者的取舍关系）不会变。
- 两条基线是**按常见做法写的参照实现**，不是对某家厂商产品的评测；写它们是为了把「本产品多做了什么」量化，不是为了给别家打分。
- 「身份槽位只看姓名与患者编号」是一条**口径约定**，已在第四节写明。若把住院号 / 检查号也算进代号，三条路径的串号率都会变成 100% —— 那衡量的是「都写了同一个占位符」，不是「分不清谁是谁」。
- 一致代号密钥来源见第二节。三项指标都与密钥取值无关，换密钥只改变代号字符串本身。
