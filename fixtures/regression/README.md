# 误伤回归语料库

这个目录放的是**不能被脱敏改写**的东西：病名、药名、科室名、检验项目名，
以及一批和身份证 / 住院号长得极像的干扰项。

脱敏产品最容易被投诉的不是「漏脱」，而是「脱过头」——把剂量当住院号抹掉、
把检验项目编码当检查号抹掉、把「姓名：未登记」抹成「姓名：<患者姓名>」，
临床数据就失真了，科室回头根本没法用。���个目录就是这条防线的回归底座。

## 文件

| 文件 | 内容 | 期望 |
|------|------|------|
| `corpus.jsonl` | 误伤回归语料（一条一行 JSON） | 正文**逐字不变**，身份类命中数为 **0** |
| `negative_controls.jsonl` | 对照项：**必须被脱**的真身份 | 确认档命中且正文被改写 |

## 字段

```json
{"id": "R001", "category": "病名", "text": "右肺下叶磨玻璃结节", "expect": "keep", "note": "自由说明"}
```

- `id`：条目编号，唯一；
- `category`：`病名` / `药名` / `科室名` / `检验项目名` / `干扰项`；
- `text`：放进正文的那一行（单独一段文本喂给主路径）；
- `expect`：目前只有 `keep`（正文不变）一种取值；
- `note`：这条为什么容易误伤、靠哪一层挡住（自由文本，给人看）。

## 怎么加一条

1. 写一行真实风格的材料片段（从真实报告里抄一段，**不要**编造患者身份）；
2. 归类、给唯一 `id`、写一句 `note` 说明它像什么；
3. 跑 `pytest tests/test_allowlist.py -q` —— 有一条被改写或有身份类命中就会红。

## 挡它的是哪一层

| 形态 | 例子 | 靠哪一层挡 |
|------|------|-----------|
| 临床词 | 右肺下叶磨玻璃结节 | 压根不产生命中（没有编号形状） |
| 数字语义 | 30mL、128.50 元、第 2 页、12床 | 数字类歧义消解（识别**之前**判定） |
| 字段位置的非人名取值 | 姓名：未登记 / 新生儿 / 本人 | 白名单 exact |
| 系统占位值 | 住院号：NONE / NULL / PENDING | 白名单 regex |
| 全零 / 掩码号 | 0000000 / MZ000000 / XXXXXXX | 白名单 regex |
| 检验项目编码 | JC + 10 位数字（与检查号同形） | 白名单 regex（按位数与检查号区分） |
| 形似编号但证据不足 | 标本编号：20260105 | 告警档：进清单留痕，不改写正文 |
| 形似身份证但校验位不过 | 18 位串 | 告警档：不判为身份，不计入残留 |

白名单内容在 `policy/research.yaml` → `allow_list` 段；改那里即可换院区写法，
不用改代码。**白名单只放行「确定不是身份」的取值** —— 形态写宽了会把真住院号
一起放过（漏脱比脱过头更糟）。

## 数据来源

全部为程序自造的合成文本，不含任何真实患者信息；编号类取值沿用项目既有
样例里的占位写法（`90000001` / `CHK0000001` / `110101194912310010` 等）。
