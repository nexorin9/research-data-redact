# 视觉目标卡 · 科研影像数据脱敏系统

> 本轮交付形态为**事件驱动守护**（常驻进程 + 运维 CLI），**无图形界面**。
> 因此视觉目标锁定在**服务运行日志**（终端会话 + 结构化日志行），不是 Web 大屏、不是一次性导出表。
> 本环境不具备图像生成能力，故只保留本结构化视觉目标卡 —— **不伪造概念图、不放占位图**。
> 真实运行证据在 Phase 4 采集到 `docs/screenshots/`，README「概念 / 实测对照」小节做并排诚实对照。

## 三个状态

### 1. 起始态 —— 配置装载回执 + 心跳

终端里跑 `python -m research_redact.daemon`，首屏是**配置装载回执**，逐行打印：

```
2026-10-31 06:20:08 | info  | policy-loaded       | 策略表 policy/research.yaml 已载入（12 条实体规则）
2026-10-31 06:20:08 | info  | channel-configured  | 主索引端点已配置（凭据来自环境变量，值不回显）
2026-10-31 06:20:08 | info  | channel-configured  | 交付通道已配置（科研数据平台）
2026-10-31 06:20:08 | info  | daemon-ready         | 等待交付目录投放申请单
2026-10-31 06:20:11 | idle  | heartbeat           | waiting-for=./var/inbox | queue=0
```

画面元素：
- 每一行一个事件，**一行一条**，字段间以 ` | ` 分隔；
- 凭据值**一律不回显**，只出现「已配置 / 未配置（通道挂起）」。

### 2. 首个可用瞬间 —— 批次结果摘要 + 命中清单前几行

交付目录出现一份申请单与 3 份材料后，守护进程打出第一块**结果摘要**，同一屏下方列出命中清单前几行：

```
2026-10-31 06:20:14 | info  | batch-result        | 批次 B-20261031-0007 | 材料 3 份 | 命中身份实体 12 处 | 生成代号 3 个（跨材料一致）| 残留告警 0
    │ 1  PATIENT_NAME   off 12   score 0.98  命中清单：主索引名单匹配（主键 P-3f9a…）
    │ 2  VISIT_NO       off 31   score 0.96  命中清单：住院号格式 + 邻近上下文「住院号」
    │ 3  ID_CARD        off 58   score 0.99  命中清单：18 位 + GB 11643 校验位通过
    … 其余 9 条见清单文件 outbox/B-20261031-0007/manifest.jsonl
```

画面元素：
- **只显示字段位置 / 实体类型 / 置信分 / 解释**，**不显示命中原文**（安全审计红线）；
- 命中清单默认展开 10 条，其余折叠为一行 `… 其余 N 条见清单文件`。

### 3. 成形态 —— 批次时间线 + 两列待办 + 滚动心跳

常驻日志跑成一张**批次时间线**，每批次一行，右侧两列分别是「待人工确认」与「还原请求（含双人授权状态）」，底部滚动心跳与异常行：

```
2026-10-31 06:20:14 | info  | batch-result | B-20261031-0007 | 例 3 | 命中 12 | 残留 0 | 已投递 | 推送 06:20:15
2026-10-31 06:20:19 | info  | batch-result | B-20261031-0008 | 例 1 | 命中  7 | 残留 0 | 已投递 | 推送 06:20:20
2026-10-31 06:20:26 | warn  | batch-suspended | B-20261031-0009 | 主索引端点超时 → 本批次挂起，不静默放行
2026-10-31 06:20:31 | info  | restore-request  | B-20261031-0007 | 授权人 A 已签字 | 授权人 B 待签字 | 到期 2026-10-31 18:00
2026-10-31 06:20:33 | idle  | heartbeat | waiting-for=./var/inbox | queue=1 | pending-restore=1
```

## 视觉语言

| 项 | 取值 |
|---|---|
| 字体 | 等宽：`ui-monospace, SFMono-Regular, "SF Mono", Menlo, Consolas, "Liberation Mono", monospace` |
| 正常态 | `#1A7F37` |
| 告警态 | `#B26B00` |
| 失败态 | `#B42318` |
| 分隔与轴线 | `#6B7280` |
| 正文 | `#111827` |
| 背景 | 默认终端背景（深色主题下亦可读） |

**信息层级（三层，一眼可分）**
1. **第一层 = 批次结果行** —— 唯一加粗 + 左侧竖线 `│`，是用户每屏最需要看到的；
2. **第二层 = 命中清单行** —— 缩进、灰色、无加粗，位置 / 类型 / 分数 / 解释；
3. **第三层 = 心跳与异常行** —— 最浅，仅一行一事件，不抢视线。

**留白密度**
- 每行一条事件；**事件之间留 1 空行**；
- 命中清单默认展开 10 条，其余折叠为 `… 其余 N 条见清单文件`；
- 同一批次的多行共享一个左侧竖线，读起来是一条时间线而不是一堆日志。

## 必须可达的约束

- 只用当前技术栈真能画出上述画面：Python 标准库 `logging` + 简易 ANSI 着色 + SQLite 状态表；
- **不出现**仪表盘图表、实时大屏、WebSocket 面板、图表控件或任何依赖未装库的组件；
- 颜色只靠 ANSI 转义序列与终端主题，不引入图形库；
- 时间统一 `YYYY-MM-DD HH:mm:ss`，批次号、命中数、耗时等数字用等宽字体右对齐（tabular-nums 效果由等宽字体保证）。

## 实测口径校正（Phase 4 · task 40 记录）

本卡是**立项期的视觉目标**，不是实测截图。实际实现（`src/research_redact/logging_setup.py`）
与上面这张卡有**两处刻意的偏差**，如实记在这里：

| 卡上的目标 | 实际实现 | 为什么 |
|------------|----------|--------|
| 竖线分隔的人读格式（`时间 \\| 级别 \\| 事件 \\| 字段`）+ ANSI 着色 | **一行一条 JSON（JSONL）**，8 个标准字段恒定存在（时间 / 级别 / 事件 / 批次号 / 材料数 / 状态 / 耗时 / 错误码），不适用写 `null` | 守护进程是**无人值守**的：日志要被日志采集器收走、要能被 `grep` / `jq` 直接筛。人读格式是这层 JSON 的**渲染**问题，不是数据格式问题 —— 同一份记录换个渲染器就能变成卡片里的样子 |
| 命中清单默认展开 10 行、其余折叠为一行 | 命中清单**只落文件**（`outbox/<批次>/manifest.jsonl`），终端只报条数与摘要，不逐条刷屏 | 500 例语料下逐条刷屏会把真正的异常行淹掉；清单按需查，不占值班终端 |

其余对齐：每行一条事件、凭据值一律不回显、时间线与心跳按固定间隔打出、命中清单不显示原文 —— 这几条实测与卡片一致。
